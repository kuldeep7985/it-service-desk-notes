## ⚙️ ServiceNow — What I Practiced

### Creating an Incident Ticket
```
ServiceNow → Incident → New

Fields filled:
- Caller          : Test User
- Category        : Network
- Subcategory     : Connectivity
- Priority        : 2 - High
- Short Description: "User unable to access shared drive"
- Description     : Detailed issue description
- Assignment Group: IT Support Team
→ Submit
```

### Ticket Lifecycle Followed
```
New → Assigned → In Progress → Resolved → Closed

State 1 (New):
  Ticket created, not yet assigned

State 2 (Assigned):
  Assigned to IT Support technician

State 3 (In Progress):
  Technician working on the issue

State 4 (Resolved):
  Solution applied, waiting for user confirmation

State 5 (Closed):
  User confirmed issue resolved
```

### SLA Tracking
```
Priority 1 (Critical) : Response 1hr  | Resolution 4hrs
Priority 2 (High)     : Response 4hrs | Resolution 8hrs
Priority 3 (Medium)   : Response 8hrs | Resolution 24hrs
Priority 4 (Low)      : Response 24hrs| Resolution 72hrs
```

## 🔧 Common IT Support Issues & Solutions Practiced

| User Issue | Troubleshooting Steps | Solution |
|---|---|---|
| No internet access | Check cable → ipconfig → ping gateway → ping 8.8.8.8 | Reset adapter / Check DHCP |
| Can't login to domain | Check network → Verify credentials → Check AD account status | Unlock AD account |
| Outlook not working | Check internet → Test SMTP → Check credentials | Reconfigure mail profile |
| Slow PC | Check Task Manager → CPU/RAM usage → Startup programs | Disable startup apps |
| Printer offline | Check connection → Restart spooler → Reinstall driver | Update/reinstall driver |

## 📋 Ticket Handling Best Practices Learned

```
1. ALWAYS acknowledge the ticket immediately
2. Set correct priority based on business impact
3. Update ticket status at every step
4. Add detailed notes for each action taken
5. Never close ticket without user confirmation
6. Escalate to L2/L3 if not resolved in SLA time
7. Document solution for knowledge base
```
